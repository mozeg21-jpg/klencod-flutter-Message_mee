 Ahmed Saad Community — الإصدار الثالث عشر (v13)
 إصلاح فشل التوقيع في GitHub Actions:
 ملف release-key.jks غير موجود أثناء validateSigningRelease
========================================================

1) إجابة سريعة على سؤالك: "كل مرة أبني فيها مشاكل ولا إيه؟"
--------------------------------------------------------
لأ يا دكتور — الأخطاء الحمراء اللي ظهرت كانت مشكلتين محددتين
اتصلحوا واحدة واحدة، ومعظم اللوج اللي شفته طبيعي:

• v10: خطأ Dart (AndroidForegroundServiceType) → اتصلح في v11.
• اللوج الأخير وصل لمرحلة التجميع الفعلي: تنزيل NDK، تثبيت CMake،
  ضغط خطوط الأيقونات (tree-shaking)، وتجميع Java — وده معناه إن
  كود Dart سليم تمامًا.
• الخطأ الأحمر الوحيد المتبقي كان سطر واحد:
  > Execution failed for task ':app:validateSigningRelease'.
  > Keystore file '.../android/app/release-key.jks' not found
    for signing config 'release'.
• تحذيرات "will soon be dropped" الخاصة بـ Gradle / AGP / Kotlin
  ليست أخطاء؛ هي إنذارات مستقبلية والبناء يكمل عادي معاها.

2) ليه حصل خطأ التوقيع ده تحديدًا؟
--------------------------------------------------------
• ملف android/app/release-key.jks (مفتاح التوقيع) مستبعَد من Git
  عبر .gitignore — وده طبيعي؛ مفاتيح التوقيع لا تُرفع للريبوهات.
• في الـ CI يُعاد توليد المفتاح من android/signing/release-key.jks.b64.
• لو مجلد android/signing/ ما اترفع كاملًا، أو وُجد ملف key.properties
  بلا ملف JKS المقابل، يتوقف البناء عند فحص التوقيع قبل خروج APK.

3) إصلاحات v13 (ثلاث طبقات ضمان عشان البناء ما يوقفش أبدًا)
--------------------------------------------------------
أ) android/app/build.gradle:
   توقيع release الرسمي يُستخدم فقط لو ملف الـ JKS موجود فعليًا؛
   ولو غير موجود ينتقل البناء تلقائيًا لتوقيع debug التلقائي.
   النتيجة: الـ APK دائمًا موقّع وقابل للتثبيت، ولا يتوقف عند
   validateSigningRelease حتى لو المفتاح غاب.

ب) .github/workflows/build.yml — خطوة "Prepare signing keystore":
   1) سر KEYSTORE_BASE64 إن كان معرّفًا على المستودع.
   2) وإلا فك ترميز android/signing/release-key.jks.b64 المرفوع.
   3) ولو لا يوجد مفتاح على الإطلاق تُحذف key.properties
      ويستخدم Gradle توقيع debug التلقائي.
   مع طباعة حالة المفتاح في اللوج للوضوح.

ج) .gitignore:
   استثناءات صريحة تضمن أن مجلد android/signing/ (B64 + key.properties)
   يُرفع للمستودع ولا يتجاهله Git بأي شكل.

د) scripts/build_release.sh و scripts/build_release.bat:
   السكربت المحلي يستعيد المفتاح من ملف B64 قبل البناء،
   وإلا يكتفي بتوقيع debug التلقائي من غير ما يفشل.

4) الملفات المتغيرة في v13
--------------------------------------------------------
android/app/build.gradle
.github/workflows/build.yml
.gitignore
scripts/build_release.sh
scripts/build_release.bat
(ملاحظة v12 القديمة استُبعدت لأن تشخيصها لم يطابق اللوج الفعلي.)

5) خطوات ما بعد رفع النسخة
--------------------------------------------------------
• ارفع محتوى المجلد كاملًا على الريبو، وتأكد أن android/signing/
  فيه الملفين: release-key.jks.b64 و key.properties.
• لو الريبو عام ولا تريد رفع مفتاح إطلاقًا: لا تعمل أي إعداد
  إضافي؛ البناء يستخدم توقيع debug التلقائي والـ APK يثبت عادي.
• ملاحظة مهمة: توقيع debug التلقائي قد يختلف بين بناء وآخر؛
  لو ظهر رفض تثبيت تحديث فوق نسخة سابقة، احذف التطبيق القديم
  أولًا ثم ثبّت النسخة الجديدة.
• مفيش أي تغيير على قواعد Firebase أو شكل الرسائل والصور
  والفيديوهات والردود والتفاعلات — زي ما هي بالظبط.
