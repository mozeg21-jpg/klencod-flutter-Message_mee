 Ahmed Saad Community — الإصدار السادس (v6)

أولًا: الجديد في هذا الإصدار
--------------------------------------------------------
1) زرار صورة (أيقونة صورة جبلية) وزرار فيديو (أيقونة كاميرا)
   جنب زرار الميكروفون في شريط الكتابة.
2) الصورة والفيديو بيتخزنوا بنفس فكرة الصوت تمامًا:
   الملف يتحول Base64 نصي ويحفظ في Realtime Database مباشرة،
   بدون Firebase Storage وبدون أي مساحة تخزين مدفوعة.
3) الصورة بتتعرض جوه فقاعة المحادثة، والضغط عليها يفتحها
   ملء الشاشة مع تكبير وتصغير بإصبعين.
4) الفيديو بيشتغل جوه الفقاعة بزرار تشغيل وشريط تقدم،
   وبيتحفظ مؤقتًا على الجهاز بعد أول تشغيل.
5) الأيقونة الخارجية (على شاشة الموبايل الرئيسية) اتظبطت،
   وشملت الأيقونة التكيفية Adaptive Icons لأندرويد 8 فأعلى.
6) التطبيق بقى موقّعًا تلقائيًا، فمش هيظهر خطأ
   "الحزمة غير صالحة / App not installed" عند التثبيت.

ثانيًا: حدود الحجم (مهمة عشان قاعدة البيانات)
--------------------------------------------------------
- Base64 بيزيد حجم الملف حوالي 33% تقريبًا.
- الحد الأقصى المسموح: الصورة 4 ميجا، الفيديو 10 ميجا
  (يفضل فيديوهات قصيرة أقل من دقيقتين).
- أي ملف أكبر من كده التطبيق بيرفضه بتنبيه واضح بالعربي.
- الصور بتتضغط تلقائيًا (عرض حتى 1280 بكسل، جودة 70%)
  قبل ما تتبعت، عشان الرسالة ما تكبرش في القاعدة.

ثالثًا: خطوات التركيب بعد فك الضغط
--------------------------------------------------------
1) استبدل ملفات مشروعك الحالية بملفات هذا الإصدار.
2) في مجلد المشروع شغل:
       flutter pub get
3) توليد الأيقونة الخارجية:
       dart run flutter_launcher_icons
   (وفي بناء GitHub الأيقونة بتتولّد تلقائيًا من الـ workflow)
4) جرّب على الموبايل مباشرة:
       flutter run
5) بناء نسخة التثبيت (Release):
       flutter build apk --release
   ملف APK النهائي موجود في:
       build/app/outputs/flutter-apk/app-release.apk

رابعًا: التوقيع وحل مشكلة "الحزمة غير صالحة"
--------------------------------------------------------
سبب المشكلة: البناء القديم كان APK بدون توقيع نهائي،
وأندرويد بيرفض تثبيت أي حزمة غير موقّعة ويقول "الحزمة غير صالحة".

الملفات الجاهزة في الإصدار ده:
- android/app/release-key.jks  ← مفتاح توقيع رسمي جاهز.
- android/key.properties        ← بيانات المفتاح للبناء المحلي.
- android/app/build.gradle       ← بيستخدم المفتاح تلقائيًا،
  ولو مش موجود بيرجع لتوقيع debug التلقائي؛ وفي الحالتين
  الـ APK يطلع موقّعًا وقابلًا للتثبيت.

البناء المحلي:
- مفيش أي خطوة إضافية؛ flutter build apk --release
  بيطلّع APK موقّع مباشرة.

البناء التلقائي على GitHub Actions:
- افتح الملف الخاص android/signing-credentials.txt وفيه:
  • كلمة مرور المفتاح
  • قيمة KEYSTORE_BASE64 الجاهزة للنسخ (المفتاح كامل)
- في المستودع على جيت هاب:
  Settings → Secrets and variables → Actions → New repository secret
  وأضف 4 أسرار:
       KEYSTORE_BASE64  = القيمة الطويلة من الملف
       KEYSTORE_PASSWORD = كلمة المرور
       KEY_PASSWORD      = نفس كلمة المرور
       KEY_ALIAS         = release
- من غير إضافة أسرار: البناء بيستخدم توقيع debug التلقائي
  والـ APK يثبت عاديًا، لكن المفتاح الرسمي أفضل عشان تقدر
  تحدّث التطبيق لاحقًا بنفس التوقيع من غير مشاكل.

⚠️ تحذير أمان مهم جدًا:
- لا ترفع على GitHub نهائيًا:
      android/key.properties
      android/app/release-key.jks
      android/signing-credentials.txt
  هي مكتوبة في .gitignore بالفعل فمش هتترفع لو المشروع عليه Git.
- احتفظ بنسخة من release-key.jks وكلمة المرور في مكان آمن خارجي،
  لأن لو ضاع المفتاح مش هتقدر تحدث نسخة مثبتة سابقًا بنفس التوقيع.

خامسًا: قواعد Firebase (لو الرسائل لسه مش بتبعت)
--------------------------------------------------------
Console Firebase → مشروع muslim-d9113 → Realtime Database → Rules:
{
  "rules": {
    ".read": true,
    ".write": true
  }
}
ثم اضغط Publish.
