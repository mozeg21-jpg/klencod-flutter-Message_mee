========================================================
 Ahmed Saad Community — الإصدار السابع (v7)
 البناء والتوقيع التلقائي بالكامل (صفر إعدادات يدوية)
========================================================

فكرة النسخة دي: ما فيش خطوات توقيع يدوية ولا أسرار مطلوبة.
أول ما ترفع الكود على GitHub، البناء والتوقيع والنشر يحصلوا
لوحده، وتنزل ملف APK جاهز للتثبيت على طول.

--------------------------------------------------------
1) على GitHub — الطريق التلقائي الأسهل (مُوصى به)
--------------------------------------------------------
1. ارفع المجلد على مستودعك على جيت هاب (push).
2. افتح التبويب Actions → هيشغّل "Flutter APK Build (Signed Automatically)"
   لوحده، وبيعمل بالترتيب:
      • يجلب الاعتماديات (flutter pub get)
      • يولّد أيقونة التطبيق الخارجية تلقائيًا
      • يفك مفتاح التوقيع ويبني نسخة Release موقعّعة
3. استلم ملف APK من مكانين:
   • Actions → آخر تشغيل → Artifacts → app-release-apk
   • Releases → أحدث إصدار اسمه "latest" → ملف app-release.apk
     (ده رابط تنزيل مباشر تقدر تبعته لأي حد يثبت عليه فورًا).

ملحوظة: مفيش أي Secrets مطلوبة في الوضع الافتراضي. لو المستودع
أصله خاص (مجتمع صغير) كده كافي تمامًا.

--------------------------------------------------------
2) البناء على جهازك المحلي بضغطة واحدة
--------------------------------------------------------
• ويندوز: انقر نقرًا مزدوجًا على:
      scripts\build_release.bat
• لينكس / ماك:
      chmod +x scripts/build_release.sh
      ./scripts/build_release.sh
• السكربت بيعمل تلقائيًا:
      flutter pub get
      dart run flutter_launcher_icons
      flutter build apk --release
  والناتج الموقّع:
      build/app/outputs/flutter-apk/app-release.apk

--------------------------------------------------------
3) الملفات الجديدة في v7
--------------------------------------------------------
android/signing/release-key.jks.b64  ← مفتاح التوقيع بصيغة Base64
android/signing/key.properties       ← بياناته (يُنسخ وقت البناء)
scripts/build_release.sh / .bat      ← سكربت البناء بضغطة واحدة
.github/workflows/build.yml          ← توقيع تلقائي + رفع APK في Releases

--------------------------------------------------------
4) ملاحظة أمان مهمة (اقرأها مرة واحدة)
--------------------------------------------------------
• المفتاح موجود داخل المستودع عشان التوقيع يبقى تلقائيًا بدون
  إعداد، وده مناسب تمامًا لتطبيق مجتمعي بيُثبّت مباشرة من APK.
• لو المستودع عندك عام على GitHub، أو ناوي تنشر التطبيق على
  Google Play، حوّل المفتاح لأسرار المستودع (Settings → Secrets
  and variables → Actions):
       KEYSTORE_BASE64 = محتوى android/signing/release-key.jks.b64
       KEYSTORE_PASSWORD = كلمة المرور من android/signing/key.properties
       KEY_PASSWORD = نفس كلمة المرور
       KEY_ALIAS = release
  والـ workflow هيستخدم الأسرار تلقائيًا بدل المفتاح المرفق.
• احتفظ بنسخة من المفتاح خارج الجهاز؛ لو ضاع مش تقدر تحدّث
  نسخة مثبتة سابقًا بنفس التوقيع.

--------------------------------------------------------
5) خطوات خارج الكود بتتعمل مرة واحدة بس
--------------------------------------------------------
• Firebase Console → Realtime Database → Rules:
       { "rules": { ".read": true, ".write": true } }
  ثم Publish (لو الرسائل بتظهر "تعذر الإرسال").
• أول تشغيل على الموبايل: اسمح بأذونات الميكروفون والمعرض
  من إعدادات التطبيق.

--------------------------------------------------------
6) تذكير بحدود الوسائط (الصور والفيديوهات)
--------------------------------------------------------
• الصورة حتى 4 ميجا، الفيديو حتى 10 ميجا (Base64 يزيد الحجم
  حوالي 33%) حتى لا تثقل قاعدة البيانات.
--------------------------------------------------------
7) إصلاح نسخة v8: تعطل أمر الأيقونات على GitHub
--------------------------------------------------------
• كان إعداد ios: true رغم أن المشروع أندرويد فقط (لا يوجد
  مجلد ios) فينهار الأمر بخطأ Icon-App-20x20@1x.png غير موجود.
• الإصلاح: ios: false في pubspec.yaml، وأصبح خطوة توليد
  الأيقونات غير مانعة للبناء (|| true) فالـ APK يطلع موقعّعًا
  حتى لو حدثت أي مشكلة في الأيقونات.
